# Fruito Pao 2.0 — утверждённый handoff для Claude

## 1. Источник истины

Реализовать направление по двум эталонам:

- `reference/menu-approved.png` — главное меню;
- `reference/gameplay-approved.png` — игровая сцена и визуальная иерархия.

Эталоны показывают стиль и композицию, но не являются готовым фоном. Нельзя
вставлять весь mockup одной картинкой. Интерфейс собирается из DOM/CSS, текущих
фруктов и ассетов `src/assets/redesign-v2/`.

## 2. Границы задачи

Claude меняет только разметку и визуальный слой. Запрещено менять:

- сетку 12×6, правила поиска пары, Group/Time/Classic и баланс уровней;
- жизненный цикл баннера: показать при входе в режим, убрать при выходе;
- `src/utils/admob.ts`, Families flags, `npa`, ad unit, interstitial timing;
- Android/Capacitor-конфигурацию;
- момент появления результата и переходы между уровнями.

Работать только в `main`. Перед началом подтянуть актуальный `main`.

## 3. Геометрия 720×405

Сцена остаётся фиксированной и масштабируется существующим `SceneWrapper`.

| Зона | Координаты/размер | Правило |
|---|---:|---|
| HUD | x 35–685, y 10–62 | Набор отдельных капсул, не одна длинная панель |
| Поле | x 70–650, y 62–347 | Максимум 580×285 |
| Баннер safe-zone | y 352–405 | Полностью пусто от игрового UI |

Нативный адаптивный баннер рисуется поверх WebView. Поэтому ни плитки, ни
кнопки, ни модалки результата не должны опускаться ниже `y=352`. В браузерной
версии эту полосу не подписывать и не рисовать как рекламу: оставить фон.

## 4. Плитки — главное изменение

Старые белые одинаковые карточки больше не использовать.

Каждой заполненной плитке назначить один из четырёх цветов по стабильному
правилу `tile.type % 4`: aqua, mint, coral, lemon. Градиенты брать из
`src/assets/redesign-v2/_tokens.scss`. Поверх CSS-фона положить
`ui/tile-gloss.svg`, затем фрукт.

- размер фрукта: 88–92% клетки;
- внутренний padding: максимум 1–2 px;
- фрукт не менять по opacity в selected-состоянии;
- пустая клетка не имеет фона, рамки и тени;
- тень плитки: `0 2px 3px rgba(7,94,114,.32)`;
- border-radius: 22–25% от ширины клетки;
- вся плитка должна выглядеть цветной, фрукт остаётся главным контрастом.

Selected: поднять визуально на 2 px, добавить бело-мятное двойное кольцо и
лёгкий glow. Group selected использует янтарное пунктирное кольцо. Ошибка —
коралловый контур и короткий shake, но не непрозрачный крест поверх фрукта.

## 5. Поле

Использовать `ui/board-frame.svg` как растягиваемую рамку 580×290. В текущей
реализации поле 12×6 и служебные внешние клетки уже вынесены за контейнер —
эту геометрию сохранить. Подложка
внутри должна быть спокойнее плиток: тёмно-бирюзовая прозрачность 22–30%, blur
4–6 px. Детали фоновой картинки под полем не должны конкурировать с фруктами.

Поле центрировать. Нельзя растягивать обратно до 690 px: это вернёт конфликт с
баннером. Если на реальном устройстве баннер выше safe-zone, уменьшать только
поле пропорционально, сохраняя центрирование.

## 6. HUD

Заменить длинную общую панель отдельными капсулами на основе
`ui/hud-pill.svg`: Back, Level, Timer, Shuffle, Score. Высота 42–48 px. Текст
тёмно-синий (`#123d66`), цифры крупнее подписей. Timer может иметь зелёную
заливку, но форма и блик должны совпадать с остальными капсулами.

На 640×300 разрешается компактный вариант: высота HUD 36 px, поле уменьшается
пропорционально, gap между капсулами 4 px. Элементы не должны переноситься.

## 7. Меню

Композиция как в `menu-approved.png`: логотип слева, три крупные кнопки справа.
Кнопки получают разные акцентные цвета: Classic — aqua, Time — coral,
Group — lemon. Минимальная зона нажатия 48 px. На 640×300 уменьшить логотип и
вертикальные gaps; все три кнопки и Privacy Policy обязаны оставаться видимыми.
Баннер на главном меню не резервировать.

## 8. Микроанимации

| Событие | Анимация | Длительность |
|---|---|---:|
| tap | scale 1 → .94 → 1, тень короче | 100 ms |
| selected | translateY -2 px + кольцо fade-in | 140 ms |
| верная пара | кольцо, sparkle, scale 1 → 1.08 → .65, fade | 220 ms |
| ошибка | translateX 0/-3/3/0 + coral outline | 180 ms |
| shuffle | fade .75 + stagger 14 ms | 260–320 ms |
| +score | число летит к Score и затухает | 420 ms |
| открытие результата | backdrop 160 ms, карточка .9 → 1 | 220 ms |

Для `prefers-reduced-motion: reduce` убрать scale/translate и оставить только
fade 100–140 ms.

## 9. Порядок внедрения

1. Подключить `_tokens.scss`, цветные плитки и `tile-gloss.svg` во всех режимах.
2. Подключить `board-frame.svg`, проверить 12×6 и пустые клетки.
3. Разбить HUD на капсулы, не меняя обработчики и данные.
4. Перекомпоновать меню и цветные кнопки.
5. Проверить Classic, Time, Group, selected, match, error и result.
6. Сделать скриншоты 720×405 и 640×300.
7. На Android проверить реальный adaptive banner: последний ряд поля виден и
   доступен для нажатия целиком.
8. Выполнить `pnpm build:prod`; `docs/` обновлять только этой командой.

## 10. Критерии приёмки

- сетка реально 12×6 и механика не изменилась;
- плитки заметно цветные и отличаются от прежних белых карточек;
- фрукты одного визуального масштаба и не теряются на фоне;
- HUD состоит из капсул и читается на телефоне;
- нижние 53 px сцены свободны для баннера;
- меню полностью помещается в 640×300;
- все состояния читаются не только прозрачностью;
- production build проходит, PNG-эталоны открываются и имеют IEND/валидный CRC.

## 11. Промпты генерации эталонов

Эталоны созданы встроенной генерацией изображений. Исходные production-промпты
зафиксированы в `PROMPTS.md`; их можно повторять для новых согласованных
вариантов, но Claude не должен самостоятельно заменять утверждённые PNG.
